A visual tutorial · gpu-cluster-readiness

Your cluster has 512 GPUs.
Can it run anything?

Buying GPUs is the easy part. Proving a cluster is ready to run real work, that is a skill. This tutorial teaches it, one picture at a time.

Watch the nodes light up. Two are ready. The third one looks identical, and it can run nothing. Telling them apart is the whole job.

01The one idea: capacity is not readiness

Every Kubernetes node reports two numbers for its GPUs. Capacity is what the hardware claims. Allocatable is what the scheduler can actually hand to a workload. The gap between them is where clusters lie.

node-03 capacity
8 GPUs
node-03 allocatable
0 GPUs
after plugin fix
8 GPUs

The device plugin is the small DaemonSet that advertises GPUs to Kubernetes. When it dies, the hardware still reports its capacity, but allocatable drops to zero and every GPU workload pends forever. A node reporting 8 GPUs with no working plugin is not ready. That single judgment is the seed of the entire readiness discipline.

02The five checks

A readiness tool is just this judgment, made systematic. Each check answers one question and, this matters, produces evidence, not a vibe.

Check 1

Node inventory

What does every node claim, and what can it actually give? Capacity vs allocatable, per node and totalled.

Check 2

Plugin + Operator health

Is the GPU Operator's device plugin running on every GPU node? This is the check that catches node-03.

Check 3

Driver / CUDA sanity

Is a driver present, and is the version consistent across the fleet? Skew here means mysterious failures later.

Check 4

vLLM smoke benchmark

Serve a real model and measure it. 0 tokens/sec, recorded, is proof. "It deployed" is not.

Check 5

NCCL smoke test

Can the GPUs talk to each other? Training lives or dies on this. No GPUs present? The check skips, cleanly, and says why.

The product

The report

Every verdict, with the evidence behind it, in JSON + Markdown. The report is what a team signs. The report is the product.

04The certification report

When every check has run, the tool writes the artifact a platform team can sign off on:

CERTIFIED
Cluster Readiness Report · prod-gpu-01
node-inventory ....... PASS · 24 GPUs, 24 allocatable
device-plugin ........ PASS · 3/3 nodes advertising
driver-cuda .......... PASS · 550.54.15, no skew
vllm-smoke ........... PASS · 1,840 tok/s generation
nccl-smoke ........... PASS · all-reduce 41 GB/s
Verdict: PRODUCTION READY

A cluster that fails gets the same report, with the failing check named and its evidence attached. That honesty is what makes the certificate worth anything.

05Try it yourself

The tool is open source and built in the open, one check at a time.

git clone https://github.com/bishowpratap7/gpu-cluster-readiness
go run ./cmd/readiness

No GPU? Perfect first test. On a GPU-less cluster the correct inventory answer is zero, reported honestly. A tool that invents GPUs fails the only test that matters. Zeros are a pass.
